# 実装済み範囲 作業ログ (docs8.md)

本ドキュメントは、部費管理アプリ（Club Abacus System）の開発において、現在（フェーズ1・2完了、スケルトン構築時点）までに実装済みの範囲と各コンポーネントの状態をまとめたものです。

---

## 1. 全体アーキテクチャとディレクトリ構成

システムは、フロントエンド、バックエンドAPI、Discord Bot、およびデータベース（Docker）から構成される「モノレポ」構成となっています。

```text
Club-Abacus-System/
├── docs/                  # 設計・ルール関連ドキュメント
│   ├── docs1.md           # 要件定義書
│   ├── docs2.md           # 詳細設計書
│   ├── docs3.md           # 開発運用および役割分担計画書
│   └── docs8.md           # 【新規作成】実装済み範囲・作業ログ
├── backend/               # バックエンドAPI (ASP.NET Core / C#)
├── frontend/              # フロントエンド (React + Vite)
├── bot/                   # Discord Bot (Python)
└── docker-compose.yml     # データベースコンテナ設定 (PostgreSQL)
```

## 2. 実装済み範囲詳細

### 2.1 データベース & インフラ (`docker-compose.yml`)
- **PostgreSQL 16** (Alpineベース) のコンテナ定義を `docker-compose.yml` に定義済み。
- ローカルポート `5432` にマッピング。データ永続化用のボリューム `pgdata` も定義。
- `docker-compose up -d` コマンドで起動し、バックエンドからの接続を受け付けます。

### 2.2 バックエンド (`backend/`)
ASP.NET Coreを利用したAPIサーバーの基盤が実装されています。

- **データモデル定義 (`backend/Models/`)**:
  設計書（`docs2.md`）に基づき、以下のエンティティ（C#クラス）を作成済み。
  - `User.cs` (ユーザー情報)
  - `Role.cs` (役職/ロール)
  - `Permission.cs` (操作権限)
  - `UserPermission.cs` (ユーザーと権限の中間)
  - `RolePermission.cs` (ロールと権限の中間)
  - `ExpenseRequest.cs` (申請データの親ヘッダー)
  - `ExpenseItem.cs` (申請の明細データ)
  - `ExpenseDocument.cs` (領収書・見積書ファイル情報)
  - `AuditLog.cs` (操作ログ)
  - `Enums.cs` (ステータス・タイプ等の列挙型)

- **データベースコンテキストと移行 (`backend/Data/`, `backend/Migrations/`)**:
  - `AppDbContext.cs` を用意し、上記モデルを PostgreSQL 用にマッピング済み。
  - Entity Framework Core（EF Core）を使用した初期マイグレーション（`InitialCreate`）が作成済みで、データベース内にテーブルが自動生成されます。

- **ルーティング・初期API設定 (`backend/Program.cs`)**:
  - CORSポリシー設定（フロントエンドポート `5173`, `3000` からの通信を許可）
  - Swagger UIの設定完了（`http://localhost:5000/swagger` からAPI定義を確認可能）
  - 疎通確認用エンドポイント `/api/health` (正常起動時に `{"Status": "OK"}` を返却)

> **※注意**: コントローラー（APIの中身）は現在未実装です。データ操作を伴う実際のAPI機能は、今後のフェーズで実装されます。

### 2.3 フロントエンド (`frontend/`)
React (Vite) を用いたUIのスケルトンと、一部のモック（ダミーデータ）ロジックが実装されています。

- **ルーティング (`frontend/src/App.jsx`)**:
  - `react-router-dom` を用いた画面遷移ルーティングを設定済み。
  - 認証状態（`authToken`）の有無に応じたプライベートプレビュー制御（未ログイン時の `/login` への自動リダイレクト）を実装。

- **UI画面 (`frontend/src/pages/`)**:
  - **ログイン画面 (`Login.jsx`, `Login.css`)**:
    - メールアドレスとパスワードの入力フォーム。
    - 現在はモック処理となっており、任意の入力で「ログイン」ボタンを押すとダミーのトークンを LocalStorage に保存し、ダッシュボードへ遷移します。
  - **ダッシュボード画面 (`Dashboard.jsx`, `Dashboard.css`)**:
    - 予算残高、承認待ち件数、未報告アラート件数を表示（モック表示）。
    - 新規申請、管理画面、金種計算、ログアウトボタンへの導線を設置。
  - **新規経費申請画面 (`ExpenseForm.jsx`, `ExpenseForm.css`)**:
    - 経費情報を入力するフォームコンポーネント。
  - **金種計算画面 (`Calculator.jsx`, `Calculator.css`)**:
    - 精算時に必要となる日本円の紙幣・硬貨の枚数を算出する機能。
    - 承認済みの立替金（ダミーデータ）の合計額および個人ごとの金額から、必要な金種（1万円札〜1円玉）の枚数と金額の内訳を自動的にブレイクダウンして一覧表示するロジックを実装済み。
  - **管理画面 (`Admin.jsx`, `Admin.css`)**:
    - 申請履歴の一覧およびステータス管理等のインターフェース。

### 2.4 Discord Bot (`bot/`)
`discord.py` を用いた Bot のベース構造が実装されています。

- **エントリーポイント (`bot/main.py`)**:
  - Botクライアントクラス（`AbacusBot`）の定義、イベントトリガー（`on_ready`）、およびスラッシュコマンドの同期処理を実装。
- **拡張モジュール (`bot/cogs/`)**:
  - `budget.py`: 予算照会コマンド（`/budget`）のコグテンプレート。
  - `history.py`: 履歴照会コマンド（`/history`）のコグテンプレート。
- **通信ヘルパー (`bot/utils/`)**:
  - `api_client.py`: バックエンドAPIへリクエストを送るための共通 `HttpClient` ラッパーを定義。

## 4. 動作確認のための実行方法

1. **データベースコンテナの起動**:
   ```bash
   docker-compose up -d
   ```
2. **バックエンドサーバーの起動**:
   ```bash
   cd backend
   dotnet run
   ```
   - 動作確認: `http://localhost:5000/api/health` へのアクセス、または `http://localhost:5000/swagger` の閲覧。
3. **フロントエンドサーバーの起動**:
   ```bash
   cd frontend
   cmd.exe /c npm run dev
   # (PowerShell実行ポリシー制約を回避するため、cmd.exe経由を推奨)
   ```
   - 動作確認: `http://localhost:5173` にアクセスし、任意のログイン情報でダッシュボード画面や金種計算画面のUIを確認。
