# フロントエンド実装のセキュリティリスク分析と対策

現在のフロントエンド（React）の画面実装およびアーキテクチャにおいて、想定されるセキュリティリスクと改善策を分析し、フロントエンド側で対応可能なものを実装しました。

## 1. 認証・認可（アクセス制御）の脆弱性

### リスク: フロントエンドのみのルーティング保護
現在、`App.jsx` の `PrivateRoute` は `localStorage.getItem('authToken')` の有無のみで画面遷移を制御しています。
- **問題点**: ダミートークンをセットするだけでログインをバイパス可能です。
- **対策**: バックエンドAPI側で厳格なトークン検証（JWT等の署名確認）を必ず行う必要があります。（※バックエンド実装時に対応予定）

### リスク: ロール（権限）ベースのアクセス制御（RBAC）の欠如
- **問題点**: 一般部員でもURLを直接入力すれば、管理者専用画面が表示されてしまいます。
- **フロントエンドでの対応策**: `App.jsx` に `AdminRoute` を新設し、`localStorage` のモック権限情報（`userRole`）を元に、管理者画面へのアクセスを制御する実装を追加しました。

---

## 2. 危険な操作（破壊的アクション）に対する保護不足

### リスク: 簡易すぎる確認ダイアログ
- **問題点**: 部員の削除や「年度リセット処理」が `window.confirm()` （OKをクリックするだけ）で実行されてしまうため、誤操作リスクが高い状態です。
- **フロントエンドでの対応策**:
  - `UserManagement.jsx` のアカウント削除時、「削除する部員の名前」を `window.prompt` で入力させるフェールセーフを追加しました。
  - `AdminSettings.jsx` の年度リセット時、「リセット」という文字列を入力させるフェールセーフを追加しました。

---

## 3. 機密情報の漏洩リスク (Information Disclosure)

### リスク: Webhook URLの平文表示
- **問題点**: `AdminSettings.jsx` にて、DiscordのWebhook URLが平文で表示されており、盗み見による悪用の恐れがあります。
- **フロントエンドでの対応策**:
  - Webhook URLの入力欄を `type="password"` に変更し、デフォルトで文字をマスク（伏せ字）するよう修正しました。

---

## 4. XSS (クロスサイトスクリプティング) のリスク

### リスク: 悪意のあるファイルやテキストの注入
- **問題点**: 画像アップロード時のファイル検証漏れによるスクリプト実行リスクがあります。
- **対策**: バックエンドでの厳密なファイルバリデーションが必要です。（※バックエンド実装時に対応予定）

---
