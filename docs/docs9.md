# Bot開発状況 (docs9.md)

本ドキュメントは、Discord Bot (`bot/`) に関する開発状況と、直近の作業で実装された新規機能についてまとめたものです。
先のフェーズで未実装またはスケルトン状態であったBotの機能群について実装を進めました。

---

## 1. 新規実装機能

### 1.1 予算照会コマンドの強化 (`bot/cogs/budget.py`)
- **状態**: スケルトンから実装済みに更新。
- **実装内容**:
  - `/budget` コマンド呼び出し時に、バックエンド（現在はモックデータ）から総予算・使用済・残高を取得し、Discord の Embed で表示する処理に加え、**`matplotlib` を用いた円グラフ画像の動的生成・添付機能** を追加実装しました。
  - 視覚的に予算の消化状況を確認できるようになりました。

### 1.2 リアクションベースの部内投票機能 (`bot/cogs/voting.py`)
- **状態**: 新規追加（実装済み）。
- **実装内容**:
  - `/vote` コマンドを新規作成しました。
  - 投票のタイトル (`title`) と説明 (`description`) を引数に取り、Botが投票用のEmbedメッセージを送信します。
  - 自動的に ✅ (賛成) と ❌ (反対) のリアクションをメッセージに付与し、部内のリアクションベースでの意思決定を支援する仕組みを構築しました。

### 1.3 督促通知・ステータス更新通知バッチ (`bot/cogs/notifications.py`)
- **状態**: 新規追加（実装済み・スケルトン）。
- **実装内容**:
  - `discord.ext.tasks` を利用した定期実行ループ（バッチ処理）の基盤を実装しました。
  - 24時間ごとに定期実行される仕組みとなっており、実環境ではAPIを通じて未報告・未提出の経費申請者を抽出し、リマインドを送信する機能の土台となります。（現状はダミーのログ出力処理として動作）

### 1.4 メインモジュールの更新 (`bot/main.py`)
- **状態**: 更新完了。
- **実装内容**:
  - 新規作成した `voting` と `notifications` の両コグ（拡張モジュール）を、Bot 起動時の `setup_hook` にて読み込むように `main.py` を修正しました。

## 3. 今後の課題・Next Steps
- **バックエンド API 連携の本格化**: バックエンド（C#側）のコントローラーの実装が完了次第、`utils/api_client.py` にあるモック実装を実際の HTTP (`requests`) 通信に切り替えます。
- **通知バッチの具体化**: `notifications.py` 内のダミーループ処理を拡張し、実際に API から未提出者リストを取得して、該当ユーザーやチャンネルへ Discord メンションによる通知を行うように処理を置き換えます。
- **【要検討】証憑提出の督促頻度および通知設定の動的化について**: 
  - **現状の課題**: 現状のBot通知バッチは固定間隔での実行を想定したスケルトンになっています。
  - **推奨される改修**: 今後の運用に向けて「証憑登録の督促頻度は、申請者が経費申請時に各自で設定する」「会計担当への通知日数（デフォルト7日）は、管理者が管理画面から設定する」といった柔軟な仕組みに変更することが推奨されます。
  - **必要な対応箇所**: これを実現するためには、Bot側だけでなく **バックエンド** および **フロントエンド** 双方に変更を加える必要があります。今後の開発フェーズでの対応をご検討ください。
    - **フロントエンド (`frontend/`)**: 申請フォーム (`ExpenseForm.jsx`) への「リマインド頻度選択UI」の追加、および管理画面への「通知日数設定UI」の追加。
    - **バックエンド (`backend/`)**: `ExpenseRequest` モデルへの頻度保存用カラムの追加、および管理者設定を保存する新規モデル (`SystemSetting` 等) の追加とAPIの実装。
